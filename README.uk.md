# webssh

**Локальна веб-панель керування** для роботи з великою кількістю SSH-з'єднань.
Це *не* браузерний SSH-шлюз — програма працює як демон на вашій власній машині
й з вашими правами, тому може редагувати `~/.ssh/config`, генерувати та
розгортати ключі, монтувати віддалені каталоги через `sshfs` і запускати ваш
рідний термінал чи файловий менеджер. Термінал у браузері теж є — як запасний
варіант для віддаленої роботи.

## Можливості (v1)

- **Інвентар** — хости з групами (ієрархія: prod/staging, за клієнтами), теги
  та нечіткий пошук. Ручне створення й редагування, `ProxyJump`/bastion,
  додаткові ssh-опції.
- **Синхронізація з ~/.ssh/config** — імпорт наявного конфігу; експорт інвентаря
  до керованого файлу `~/.ssh/config.d/inventory`, підключеного одним рядком
  `Include`. Ваш основний конфіг резервується й ніколи не перезаписується.
- **Ключі** — генерація пар ключів (ed25519/rsa/ecdsa) та розгортання публічних
  ключів на хости (`authorized_keys`) для входу без пароля. Ведеться облік того,
  що й куди розгорнуто.
- **sshfs** — монтування та розмонтування домашнього каталогу хоста, відкриття
  його у файловому менеджері.
- **Веб-браузер SFTP** — перегляд віддаленої файлової системи, завантаження в
  обидва боки, створення каталогів, перейменування й видалення — прямо в
  браузері (автентифікація через агент/ключ або одноразовий запит пароля).
- **Запуск рідних програм** — налаштовувані команди для відкриття вашого
  термінала чи файлового менеджера.
- **Веб-термінал** — сесія xterm.js через вебсокет (запасний варіант, коли
  рідні програми недоступні).
- **Завершується разом із браузером** — кожна вкладка тримає presence-вебсокет,
  і демон виходить за кілька секунд після закриття останньої, щоб не висіти у
  фоні. Перезавантаження сторінки не рахується; щоб демон лишався працювати,
  вимкніть це в налаштуваннях.

## Безпека

Демон має широкі повноваження, тому обмежений жорстко:

- слухає **лише loopback** (відмовляється від не-loopback `--addr`);
- кожен запит потребує **стартового токена** (друкується у вигляді URL);
  початкове значення передається cookie з `SameSite=Strict`, а SPA надсилає його
  в заголовку `X-Auth-Token`;
- запити, що змінюють стан, мусять мати **loopback Origin** (захист від CSRF);
- паролі для розгортання ключів використовуються один раз і ніколи не
  зберігаються.

Не виставляйте це в мережу.

## Збірка та запуск

Потрібно: Go ≥ 1.25, Node ≥ 20, `rsvg-convert` (пакет `librsvg2-bin`, потрібен
для рендерингу іконок) і `sshfs` / `ssh-keygen` у `PATH`.

```sh
git clone https://github.com/maxx1980/tai
cd tai
make deps    # встановити залежності фронтенду (один раз)
make run     # зібрати SPA й бінарник, запустити сервер, відкрити браузер
```

Або вручну:

```sh
git clone https://github.com/maxx1980/tai
cd tai/web && npm install && npm run build && cd ..
go build -o webssh ./cmd/webssh
./webssh                 # надрукує http://127.0.0.1:8022/?token=…
```

Прапорці: `--addr 127.0.0.1:8022`, `--no-open`.

## Встановлення (стільниця Linux)

`install.sh` збирає все й реєструє webssh у меню програм:

```sh
git clone https://github.com/maxx1980/tai
cd tai
./install.sh          # залежності за потреби + збірка + пункт меню
./install.sh --run    # …і одразу запустити сервер
```

Встановлення відбувається лише у ваш домашній каталог — без root і без
системних шляхів:

- іконки → `~/.local/share/icons/hicolor/<розмір>/apps/webssh.png`
  (+ `scalable/…svg`);
- пункт меню → `~/.local/share/applications/webssh.desktop`, де `Exec` вказує на
  бінарник у цьому каталозі репозиторію, тож не переміщуйте його після
  встановлення.

Ті самі кроки доступні як `make install-desktop`. Деякі стільничні середовища
помічають новий пункт меню лише після повторного входу в систему.

Щоб видалити:

```sh
./uninstall.sh          # зупинити демон, розмонтувати sshfs, прибрати пункт меню й бінарник
./uninstall.sh --purge  # …а також видалити базу, ключі та інтеграцію з ~/.ssh
```

Звичайний виклик не чіпає нічого вашого, тож після повторного встановлення все
продовжиться з того самого місця. `--purge` питає підтвердження перед видаленням
і робить резервну копію `~/.ssh/config`, перш ніж прибрати рядок `Include`.
Розмонтування йде першим не випадково: видалення каталогу з живим sshfs-монтом
видалило б файли на віддаленому хості. Якщо потрібно прибрати лише пункт меню,
для цього досі є `make uninstall-desktop`.

## Іконки

Усі іконки рендеряться з одного джерела, `assets/icon.svg`, скриптом
`assets/gen-icons.sh` (`make icons`). `make build` запускає його автоматично, тож
favicon-и потрапляють до `web/public/` ще до того, як Vite скопіює їх у вбудований
`web/dist/`.

Бінарник ELF не може містити іконку — саме тому для Linux є `.desktop`-файл. У
Windows це можливо, через ресурс PE:

```sh
make build-windows    # go-winres збирає .syso, далі GOOS=windows go build
```

Виходить `webssh.exe` із вбудованою іконкою та відомостями про версію. Зверніть
увагу: він лише *збирається* — шар pty під Windows є заглушкою, а типові команди
термінала й монтування розраховані на Linux, тож запустити його там поки що не
вийде.

## Структура

- `cmd/webssh` — точка входу (прапорці, токен, прив'язка до loopback).
- `internal/{store,sshconfig,keys,mount,launcher,pty,server,config}` — бекенд.
- `web/` — SPA на Svelte + Vite, вбудована в бінарник через `web/embed.go`.
- `assets/` — головний `icon.svg` і скрипт, що рендерить усі растрові розміри.
- `packaging/` — шаблон `.desktop` для `make install-desktop`.
- `winres/` — маніфест ресурсів для іконки та версії під Windows.

## Плани (v2)

Прокидання портів (локальне/віддалене/SOCKS) з монітором тунелів, фонові
перевірки доступності, широкомовні команди, менеджер `known_hosts`, шифроване
сховище секретів, палітра команд, імпорт з Ansible/PuTTY.
